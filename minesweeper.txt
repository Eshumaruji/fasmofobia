For a Minesweeper college project using Java only, I'd recommend Java Swing for the GUI. It is included in the JDK, so you don't need JavaFX, FXML, or external GUI libraries.

You can use Swing for the interface and plain Java classes for all the game logic.

## 1. Recommended project structure

## Minesweeper/

Main.java

Entry point. Starts the application and opens the main game window.

MinesweeperFrame.java

Creates the main Swing window, score/status display, restart button, and difficulty controls.

GameBoard.java

Creates the grid of cells and handles mouse clicks, flagging, and interactions with the board.

Cell.java

Represents one square: whether it contains a mine, is revealed, is flagged, and how many neighboring mines it has.

MinesweeperGame.java

Contains the core rules: mine placement, revealing cells, flood-fill behavior, win/loss detection, and restarting.

GameStatus.java

An enum representing states such as READY, PLAYING, WON, and LOST.

You don't need to create all six classes immediately. For a small first version, you can combine `MinesweeperFrame` and `GameBoard`, then separate them as the project grows.

## 2. What each class is responsible for

| Class | Main responsibility |
| --- | --- |
| `Main` | Starts the game |
| `MinesweeperFrame` | Window and game controls |
| `GameBoard` | Grid display and user input |
| `Cell` | State of an individual square |
| `MinesweeperGame` | Game rules and logic |
| `GameStatus` | Current game state |

The important design principle is to keep game logic separate from GUI code. For example, `MinesweeperGame` should determine whether a player has won, while `GameBoard` should display the appropriate visual feedback.

## 4. How to represent the board

Use a two-dimensional array of `Cell` objects.

For example, a beginner-friendly board could be:

- Rows: 9
- Columns: 9
- Mines: 10

Each `Cell` should store:

- `hasMine` — whether the square contains a mine.
- `isRevealed` — whether its contents are visible.
- `isFlagged` — whether the player marked it as dangerous.
- `adjacentMines` — the number of mines in its neighboring squares.

The game can calculate `adjacentMines` after placing all mines.

## 5. Essential game mechanics

Implement these in `MinesweeperGame.java`:

1. Mine placement: Randomly place mines on the board.
2. Neighbor counting: Count mines in the eight surrounding cells.
3. Reveal cell: Reveal a safe cell and show its number.
4. Flood fill: If a cell has zero neighboring mines, automatically reveal adjacent safe cells recursively or iteratively.
5. Flag cell: Mark or unmark a suspected mine.
6. Lose condition: The player reveals a mine.
7. Win condition: All non-mine cells have been revealed.
8. Restart: Reset the board and generate new mines.

For a better playing experience, you can also guarantee that the first click never hits a mine.

## 6. GUI design using Swing

Use these Swing components:

- `JFrame` — main window.
- `JPanel` — holds the grid and top status area.
- `JButton` — individual cells in a simple implementation.
- `JLabel` — mine counter, timer, and game status.
- `JComboBox` — difficulty selection, if needed.

Use `GridLayout` to arrange the cell buttons into rows and columns. Attach mouse listeners or action listeners to handle revealing and flagging cells. A right-click can toggle a flag.

## 7. Suggested development order

- Step 1: Create a window containing a grid of buttons.
- Step 2: Create the `Cell` class and store the cells in a two-dimensional array.
- Step 3: Randomly place mines.
- Step 4: Calculate adjacent mine counts.
- Step 5: Implement revealing and flagging.
- Step 6: Add flood-fill behavior for empty cells.
- Step 7: Add win/loss detection and restart.
- Step 8: Improve the appearance and add a timer or difficulty settings.

My recommendation: Start with `Main.java`, `Cell.java`, `MinesweeperGame.java`, and `GameBoard.java`. Those four classes are enough to build a working Minesweeper game. Add `MinesweeperFrame.java` and `GameStatus.java` when you want cleaner separation and more features.
